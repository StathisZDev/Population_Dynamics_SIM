Αναγκάστηκα να αλλάξω το format των #include από #include <libs/imgui/imgui.h> σε #include "imgui.h" για να πετύχω το integration. 
Ο λόγος είναι ότι τα header files του ImPlot περιέχουν reference σε imgui.h με την μορφή #include "imgui.h" και έτσι δεν μπορεί να 
βρεθεί το αρχείο imgui.h όταν χρησιμοποιείται η μορφή #include <libs/imgui/imgui.h>. Δοκίμασα να αλλάξω τα includes μέσα στα αρχεία του ImPlot
αλλά αυτό προκαλούσε πρόβλημα στην εσωτερική λογική του ImPlot και γενικά είναι ΠΟΛΥ ΚΑΚΗ πρακτική. Ο καλύτερος τρόπος είναι τα #include να γίνονται
με την μορφή #include "imgui.h" ώστε το path να μην είναι hardcoded στο κώδικα. Ο κάθε developer θα μπορεί πρέπει να ρυθμίσει το include path στο IDE του 
ώστε να βρίσκει τα αρχεία σωστά. (Μια άλλη, πιο αυτοματοποιημένη λύση θα ήταν να χρησιμοποιηθεί κάποιο build system όπως το CMake, αλλά αυτό είναι μια άλλη ιστορία...).

- Τα wrapper functions στο utils/imgui/u_imgui.h & .cpp με μπέρδεψαν αρκετά, διότι κάνανε τη λογική του κώδικα πιο δύσκολη στην κατανόηση, ιδίως για κάποιον που δεν είναι 
εξοικειωμένος με το ImGui. Στο μέλλον, παρακαλώ, να μην χρησιμοποιούνται wrapper functions εκτός αν είναι απολύτως απαραίτητο, ώστε να διατηρείται ο κώδικας πιο καθαρός 
και ευανάγνωστος για τα υπόλοιπα μέλη της ομάδας. Εάν χρειαστεί να περιληφθούν τέτοιες συναρτήσεις πρέπει να προειδοποιηθούν τα υπόλοιπα μέλη και να περιληφθούν σχόλια που να
εξηγούν το σκοπό της συνάρτησης.

- Μετονόμασα την συνάρτηση `ImGui::Test()` σε `ImGui::DisplayData()` και μετακίνησα τη γραμμή `ImGui::Render()` ΕΞΩ από τη συνάρτηση. Παρακαλώ, μην βάζετε 
το `ImGui::Render();` μέσα στις συναρτήσεις των παραθύρων. Μονάχα ΕΝΑ Render χρειάζεται στο τέλος αφού έχουν γίνει όλα τα παράθυρα. Αν κλειστεί μέσα σε συνάρτηση μπορεί να μπερδευτεί κάποιος
και να γράψει και δεύτερη φορά.

Συνεπώς, σχολίασα την δεύτερη από τις δύο συναρτήσεις στο u_imgui.cpp (την ImGuiTest) και περιέλαβα τον κώδικά της απευθείας στο main.cpp. 

Οι υπόλοιπες αλλαγές στον κώδικα, για όποιον ενδιαφέρεται είναι σχολιασμένες. Σε μελλοντικό χρόνο τα σχόλια φυσικά θα σβηστούν.

Δημιούργησα ένα νέο αρχείο `constants.h` στο οποίο μετέφερα ορισμούς σταθερών ΑΠΟΚΛΕΙΣΤΙΚΑ για το `u_implot.h` για ευκολότερο χειρισμό τους. Οι ορισμοί περιέχονται σε ξεχωριστό 
namespace με το όνομα UImPlot για αποφυγή σύγκρουσης ονομάτων.

- ’λλαξα το standard από C++14 σε C++17 στο project settings για να μπορέσω να χρησιμοποιήσω το inline specifier στο αρχείο `constants.h` με ορισμούς μεταβλητών και 
όχι μόνο συναρτήσεων. Η χρήση του inline specifier προτείνεται για την αποφυγή πολλαπλών ορισμών συμβόλων (multiple definition errors) όταν οι μεταβλητές ορίζονται 
σε header files που περιλαμβάνονται σε πολλαπλά translation units. Προτείνω από εδώ και μπρος να χρησιμοποιείται το C++17 ή C++20 standard για μελλοντικά features.
