- Το wrapper function στο `CleanUpImGui()` (ορίζεται στο utils/imgui/u_imgui.cpp` με μπέρδεψε αρκετά, διότι κάνει τη λογική του κώδικα πιο δύσκολη στην κατανόηση, ιδίως για κάποιον που δεν είναι 
εξοικειωμένος με το ImGui. Στο μέλλον, παρακαλώ, να μην χρησιμοποιούνται wrapper functions εκτός αν είναι απολύτως απαραίτητο, ώστε να διατηρείται ο κώδικας πιο καθαρός 
και ευανάγνωστος για τα υπόλοιπα μέλη της ομάδας. Εάν χρειαστεί να περιληφθούν τέτοιες συναρτήσεις πρέπει να προειδοποιηθούν τα υπόλοιπα μέλη και να περιληφθούν σχόλια που να
εξηγούν το σκοπό της συνάρτησης.

- Μετονόμασα την συνάρτηση `ImGui::Test()` σε `ImGui::DisplayData()` και μετακίνησα τη γραμμή `ImGui::Render()` ΕΞΩ από τη συνάρτηση. Παρακαλώ, μην βάζετε 
το `ImGui::Render();` μέσα στις συναρτήσεις των παραθύρων. Μονάχα ΕΝΑ Render χρειάζεται στο τέλος αφού έχουν γίνει όλα τα παράθυρα. Αν κλειστεί μέσα σε συνάρτηση μπορεί να μπερδευτεί κάποιος
και να γράψει και δεύτερη φορά.

- Δημιούργησα ένα νέο αρχείο `constants.h` στο οποίο μετέφερα ορισμούς σταθερών ΑΠΟΚΛΕΙΣΤΙΚΑ για το `u_implot.h` για ευκολότερο χειρισμό τους. Οι ορισμοί περιέχονται σε ξεχωριστό 
namespace με το όνομα `UImPlot` για αποφυγή σύγκρουσης ονομάτων.

- Προσέθεσα ένα αρχείο ThirdPartyLibs.props το οποίο περιέχει το configuration για τα path στα οποία πρέπει να ψάψει ο compiler (MSVC) ώστε να λύσω το πρόβλημα με την εύρεση του αρχείου imgui.h
από τη βιβλιοθήκη ImPlot. Στο αρχείο αυτό ρυθμίζεται αυτόματα η γλώσσα σε C++17 ώστε να μπορούν να χρησιμοποιηθούν `inline` specifiers σε μεταβλητές και όχι μόνο σε συναρτήσεις (ένα μέρος του 
κώδικα εξαρτάται από αυτό). Η χρήση του inline specifier προτείνεται για την αποφυγή πολλαπλών ορισμών συμβόλων (multiple definition errors) όταν οι μεταβλητές ορίζονται 
σε header files που περιλαμβάνονται σε πολλαπλά translation units. 



- Αλλαγές στη συνάρτηση main():

- Προσέθεσα ό,τι #include ήταν απαραίτητο.
- ’λλαξα το `#include <stdio.h>` με το `#include <iostream>`.
- Έκανα πιο συγκεκριμένα τα μηνύματα λάθους κατά τα initialization checks της SDL κάνοντας χρήση του SDL_Log για μεγαλύτερη ακρίβεια 
στο είδος του λάθους με χρήση `SDL_GetError()`. Θα βοηθήσει σε πιθανό debugging.
- Δημιούργησα κάποια properties (props) για το SDL window, ώστε να μπορεί να γίνει το styling πιο εύκολα.
- Χώρισα το αρχείο σε τμήματα, προσέθεσα σχόλια για την τοποθεσία στην οποία βρίσκεται ο κώδικας κάποιων συναρτήσεων και οργάνωσα καλύτερα τη main.cpp
- Προσέθεσα μία συνάρτηση (PrintImGuiSettings()) για βασικό debugging που αφορά προβλήματα DPI scaling. 
- Προσέθεσα το `ShowStyleEditor()` του ImGui. Τα παιδιά που θα ασχοληθούν με το GUI μπορούν να το ενεργοποιήσουν και να πειραματιστούν σε real-time με το styling της εφαρμογής.
Όταν βρουν κάποιες ρυθμίσεις που τους αρέσουν, ας σημειώσουν τις αλλαγές που κάνανε και στη συνέχεια ας πάνε στη συνάρτηση `SetStyling()` (βρίσκεται στο u_imgui.cpp) και ας προσθέσουν/αλλάξουν
τις γραμμές που πρέπει στον κώδικα. Π.χ., εάν αλλάξουν το WindowRounding σε 0.2f στο StyleEditor, θα προσθέσουν στον κώδικα της συνάρτησης `SetStyling()` τη γραμμή `style.WindowRounding = 0.2f` 
(ή θα αλλάξουν την τιμή της εάν υπάρχει ήδη).


Αλλαγές στο u_imgui.cpp:

- Προσέθεσα κάποιες συναρτήσεις για δημιουργία διαφόρων τύπων παραθύρων. Το παράθυρο με το line graph βρίσκεται στο u_implot.cpp. Ίσως αργότερα όλες αυτές οι συναρτήσεις που αυτοματοποιούν
τη δημιουργία διαφόρων τύπων παραθύρων να μπουν σε ένα κοινό module αφιερωμένο ειδικά στο GUI.


Styling:

Πήρα την ελευθερία να βάλω το styling που είχα παρουσιάσει στην ομάδα στο μάθημα. Αν δεν αρέσει στα παιδιά που είναι υπεύθυνα για το GUI μπορούν να αλλάξουν εύκολα τις ρυθμίσεις. 
Προσέθεσα και σχόλια ώστε να μπορεί κάποιος εύκολα να αλλάξει π.χ. το χρώμα των παραθύρων με λίγες αλλαγές στις τιμές RGB ή HEX. Πολύ χρήσιμο σχετικά 
το site HTML Color Codes: https://htmlcolorcodes.com/

Οι υπόλοιπες αλλαγές στον κώδικα, για όποιον ενδιαφέρεται είναι σχολιασμένες. Σε μελλοντικό χρόνο τα σχόλια φυσικά θα σβηστούν.
